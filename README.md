# CashLens

> 一个人就是一家公司。CashLens 让经营现金流看得清、撑得住。
> 面向一人公司与小微经营者的经营现金流可视化与决策辅助工具：把散落在微信、支付宝、票据、账单里的钱归拢成一束光，照见你下个月会不会缺钱，并在「这单接不接、报多少」的决策点给出有依据的建议。

## 它解决什么

- 收入像过山车——没人告诉你下个月能不能撑住
- 钱散在多个平台——月底对不上账是常态
- 报价靠感觉——拍脑袋定价，回头发现连成本都没覆盖

现有工具都不够：记账 App 只出报表；企业级软件一个人用不起；通用 AI 拿不到你的真实流水。

## 核心闭环

```
采集（说一句 / 拍一张 / 导一份）→ 财务状态引擎 → 决策建议 → 反馈回灌
```

## 三个核心创新

1. **财务状态引擎**——证据强度分级（流水 1.00 > 票据确认 0.85 > 主动记账 0.75 > 自报 0.10 > 系统推测 0.00），状态可升可降、会过期、能从事件账本重建。记了一笔 ≠ 现金流健康。
2. **CashPulse 现金流预测**——基于历史节奏输出未来 30/90 天现金流**区间**（90% 置信带），可信度低时如实标注「现金流不明」，数据不足时如实标注不可信，不做假装精确的点预测。
3. **假设检验闭环**——每次决策记录当初假设，账本自动检验偏差（如回款周期 3 天 vs 实际 3 周），下次报价自动参考。**（事件类型与判定逻辑已在引擎层就位，偏差标记与回灌尚未实装——账本里暂无实际记录，如实标注）**

> 当前阶段：状态引擎与 CashPulse 最小版已实现（真实计算）；**接单决策最小版已落地**（报价下限 + 三道闸门，每个数字可追到账本事件）；**假设检验回灌与登录型前端为下一阶段**。本仓库按「原型 / 早期验证」口径对外呈现（证据见 `docs/` 实弹记录，含如实披露的缺陷）。

## 编排式智能体架构

> **先把话说清**：CashLens **不是多智能体，是编排式智能体**——**1 个 Agent 按需调用 SKILL**（不是 N 个人格并行审议）。多智能体一开始确实是候选方案，但这个产品做的是金额与报价决策，多个人格互相讨论容易跑偏；单 Agent + 多 SKILL 的编排式结构更稳、更可复现，最终走的是这条。

**三个数字别混**：**当前实际在用 3 个 SKILL**（记账 accounting / 接单决策 order-decision / 现金流预测 cashflow-forecast）· **MVP 定稿 8 项功能** · **方法论侧规划 33 个 SKILL**（按 Phase 2/3 渐进补齐）。SKILL 是 Markdown 方法论文件、不是常驻进程，MCP 协议统一接入工具；LLM 层为 OpenAI 兼容统一网关，服务商可插拔。

产品运行时是一条确定性链路：金额、区间与报价全部由本地引擎计算，LLM 只做解析与措辞，不参与任何数值。（开发期在引擎工作区试过专家子代理并行审议，2026-08-28 与 09-28 两次实测留痕在 `../08-实测/`；结论是它适合开发编排，不引入产品运行时。）

## 已实现能力（2026-09-28 状态）

- **四类输入通道**：图片（JPG / PNG）、PDF（有文本层本机直读，无文本层走模型）、Excel 报销表（读表取数 + 提取表内嵌入图）、CSV 账单（微信 / 支付宝导出），统一走一个采集入口；**先判这一页是什么、再决定记不记账**——票面、付款凭证（取实付）、待支付页、订单列表、聊天 / 文字截图各有明文口径，每条都写清记或不记的原因；扫不出来的图直接建议重新上传，并在汇总里点名是哪几张；
- **聊天 / 文字截图按图里的结构记账**：不是票面时把图里文字逐行读回，只采信「人写的金额」那一类行，图里自己算出的合计不重复列；金额全部来自原文，记哪几笔由用户在待确认里决定，机器不替用户挑、不自动入账；
- **退款与重复按账实处理**：实付与退款两个数由识别读出、**净额由代码相减**（78 − 6 = 72，备注摆出三个数对账）；订单列表与付款凭证按**时间**配对（同一天且相差 ≤5 分钟算同一笔，金额只作附注），命中只说结论、没配到的如实列出并**点名是哪张图**；金额为 0 的订单行整个跳过（不建草稿，也不占汇总那句）；
- **拖拽导入与项目维度**：拖文件或拖整个文件夹，第一层文件夹名即项目名；账本按项目归集，发票号参与去重，项目改名不影响已入账的记录；**导入中途可以取消**（取消不报成「导入失败」，正在读的那张会跑完，已读出的草稿留在「待确认」里）；
- **报销表双源对账**：以表内数字为准，嵌入图的识别结果只用于核对，机器不覆盖人写的数；**核对可开关、默认关闭**（关掉时界面如实写「本次未核对表内嵌入发票」，不显示成「双源核对 0/0 张一致」）；
- **对话记账**：说一句就记（语音/文字），支持中文金额（三千 / 二九九 / 三百五）、多笔拆分、报销垫付语义；
- **多轮自由对话**：接入 LLM API 后支持连续追问与跨上下文（「那笔是哪天的？」「上个月花了多少」），未配置时自动回退规则兜底（本地零成本可用）；
- **识别 → 确认 → 入账**：记账与导入先生成待确认草稿，写入账本前必须由用户确认；左栏「待确认」面板加载即拉取草稿，逐笔可改**归属项目**与**分类**，可单笔或批量确认 / 丢弃（丢弃前先问一句，并写明账本不受影响；**丢弃是软删除，进回收站后可以一键撤回**，撤回不写任何账本事件），**不做一键直入账**；
- **接单决策最小版**：历史时薪由账本反推（收入中位数 ÷ 总工时），三道闸门（现金流垫底 / 回款周期 / 税后到手），报价下限 = 时薪 × 工时 ×（1 + 税负 + 抽成），每个数字可追到 `event_id`；缺「带工时的收入记录」时如实答「算不出」，不拿默认值假装算出报价；
- **真数据查询**：最近一笔收入/支出、本月支出分类汇总、现金流 30 天 90% 区间，数值全部由本地账本与状态引擎计算，LLM 不参与编造数值；
- **工时 / 开票 / 税务归集**：项目工时 Excel 自动认列并按人汇总出工资参考表；按客户生成开票清单；按季度归集收入，只归集事实，不算应纳税额；
- **事件账本 + 状态引擎最小版**：追加式 jsonl 账本、dedupe 幂等去重、SQLite 可重建投影、asOf 读取时计算（证据分级/健康度/状态标签）；
- **创意阐述页**：三种用户场景、证据脚注（出处可溯源）、实弹验证记录、开发路线页（见 `docs/`）。

## 仓库概览

| 路径 | 职责 |
|:--|:--|
| `backend/` | FastAPI 后端：事件账本、状态引擎、四类输入通道（图片 / PDF / 报销表 / 账单）与页面类型判定、项目归集、待确认草稿、接单决策（报价下限）、工时与开票税务归集、查询工具、对话 API（规则 + LLM 双通道） |
| `engine/` | 编排式智能体工作区：SKILL 方法论、MCP 工具服务器 |
| `frontend/` | 真数据对话式财务工作台（记账对话 + 现金流/状态面板 + 待确认面板 + 项目详情） |
| `docs/` | 网页版创意阐述页（GitHub Pages 发布，含实弹证据与出处） |
| `scripts/` | 工具脚本（票据批量识别、语音识别客户端、PDF 渲染等） |
| `samples/` | 合成演示样本（可入库；真实用户数据一律隔离） |
| `tests/` | 后端单测（pytest）与 demo 行为回归（Node，直接加载真实页面脚本断言） |

## 快速开始（原型阶段）

> **本仓库为原型，未提供在线服务。** 产品（后端 API + 前端工作台）需按下述步骤在本机启动。`docs/` 是介绍页，已单独发布为静态网站（https://davidlee2026.github.io/CashLens/），不含产品功能。账本与金额计算全部在本机完成。

```bash
# 0) 配置环境（可选：不填 LLM API Key 时对话走规则兜底）
cp .env.example .env

# 1) 后端 API（事件账本 / 状态引擎 / 对话），在 backend 目录内：
python3 -m uvicorn app.main:app
# 端口需与 frontend/next.config.ts 里 /api 的代理目标一致（前端侧可用 CASH_API 覆盖）

# 2) 前端工作台（另开一个终端），在 frontend 目录内：
pnpm install && pnpm dev
# 打开终端提示的本地地址即可对话记账 / 查现金流

# 2b) 一键启动（不想敲命令时用）
#     macOS：双击仓库根目录的 启动-CashLens.command
#     它会自检依赖、首次自动安装前端依赖、同时拉起前端与后端，等就绪后打开工作台；
#     端口已有实例时先校验那是不是本仓库这一份（看账本路径与 /api/categories 版本）：
#     是本仓库的就复用，是别的副本就让路到 8002 起，避免「新版前端配旧副本后端」；
#     Windows：暂不提供一键脚本（旧脚本因端口硬编码 8001、无副本校验已移除），按上面第 1、2 步启动。

# 3) 网页版创意阐述页：直接用浏览器打开 docs/index.html

# 4) 票据识别冒烟（识别 samples/ 合成样本）
python3 scripts/batch_recognize.py samples/

# 5) 测试
python3 -m pytest tests/            # 后端单测
node tests/demo_behavior.test.mjs   # demo 行为回归（当前 16 项）
```

> 语音识别依赖本机 ASR 工具与模型：通过环境变量 `ASR_CLI` / `ASR_MODEL` 指向本机可执行文件与模型（仓库不内置、不记录路径）。
> 启动后端 API 前请先在仓库根目录执行 `cp .env.example .env`；`.env` 已被 `.gitignore` 拦截，永不入库。

## 安全与隐私

- `.env`（密钥）、`data/`（本地账本/状态库/待确认草稿）、用户上传数据目录一律不入库（见 `.gitignore`）
- 账本与金额计算始终在本地磁盘完成；金额与现金流数值不依赖任何外部服务
- 启用云端 LLM 时，仅对话文本会发送给所选 LLM 服务商（页面上明示）；关闭 LLM 即全本地
- 网页演示在浏览器本地完成，不采集任何数据
- 纪律：AI 自报不可信 —— 本仓库每个对外声称都尽量带真实实测证据或如实标注"示意/规划"
