# CashLens

> CashLens 帮小项目制公司算清一个项目的真实成本，让下次报价有据可依。
> 做活动、广告、会展、设计这类项目制生意的公司，一单做完到底花了多少、哪些钱不该算进这一单、下次报多少才算不白干 —— 把散在微信、支付宝、票据、报销表里的钱归到一个项目上，算出一份每个数字都能追到账本记录的**项目成本表**。

## 它解决什么

- 收入像过山车——没人告诉你下个月能不能撑住
- 钱散在多个平台——月底对不上账是常态
- 报价靠感觉——拍脑袋定价，回头发现连成本都没覆盖

现有工具都不够：记账 App 只出报表；企业级软件一个人用不起；通用 AI 拿不到你的真实流水。

## 核心闭环

```
采集（说一句 / 拍一张 / 导一份）→ **你逐笔确认** → 财务状态引擎 → 决策建议 → 反馈回灌
```

## 三个核心创新

1. **财务状态引擎**——证据强度分级（流水 1.00 > 票据确认 0.85 > 主动记账 0.75 > 自报 0.10 > 系统推测 0.00），状态可升可降、会过期、能从事件账本重建。记了一笔 ≠ 现金流健康。
2. **CashPulse 现金流预测**——把历史收支按**周**聚合成桶（没记录的周也计入），输出未来 30/90 天现金流**区间**（90% 带宽，带宽按 √周数 增长而非乘天数），数据不够时直说「还推不出来」，数据不足时如实标注不可信，不做假装精确的点预测。
3. **假设检验闭环**——每次决策记录当初假设，账本自动检验偏差（如回款周期 3 天 vs 实际 3 周），下次报价自动参考。**（事件类型与判定逻辑已在引擎层就位，偏差标记与回灌尚未实装——账本里暂无实际记录，如实标注）**

> 当前阶段：状态引擎与 CashPulse 最小版已实现（真实计算）；**接单决策最小版已落地**（报价下限 + 三道闸门，每个数字可追到账本事件）；**邀请码登录页与线上部署已上线**（2026-10-19，一码一账；当前是测试期实例，只对内部试用开放，地址不在此公开）；**假设检验回灌仍是下一阶段**（事件类型与判定逻辑在引擎层，偏差标记与回灌未实装）。本仓库按「原型 / 早期验证」口径对外呈现（证据见 `docs/` 实弹记录，含如实披露的缺陷）。
>
> **形态**：网页版已加 PWA 壳（`manifest.webmanifest` + 图标 + 独立窗口），手机可「加到主屏」；**手机浏览器可直接用**（2026-10-20 真机验证：手机浏览器可完成建项目与批量记账），移动端重排尚未做。

## 编排式智能体架构

> **一句话**：**编排式智能体——1 个 Agent 按需调用 SKILL**（SKILL 是 Markdown 方法论文件、不是常驻进程，可自加）。

**三个数字别混**：**当前实际在用 3 个 SKILL**（记账 accounting / 接单决策 order-decision / 现金流预测 cashflow-forecast）· **MVP 定稿 8 项功能** · **方法论侧规划 33 个 SKILL**（按 Phase 2/3 渐进补齐）。MCP 协议统一接入工具；LLM 层为 OpenAI 兼容统一网关，服务商可插拔。

产品运行时链路很短：**1 个 Agent 选定 SKILL → 调 MCP 工具 → 本地引擎算数 → LLM 只负责解析与措辞**。金额、区间与报价全部由本地引擎计算，LLM 不参与任何数值，每一步都可复现。

## 已实现能力（2026-10-20 状态）

- **四类输入通道**：图片（JPG / PNG）、PDF（有文本层本机直读，无文本层走模型）、Excel 报销表（读表取数 + 提取表内嵌入图）、CSV 账单（微信 / 支付宝导出），统一走一个采集入口；**先判这一页是什么、再决定记不记账**——票面、付款凭证（取实付）、待支付页、订单列表、聊天 / 文字截图各有明文口径，每条都写清记或不记的原因；扫不出来的图直接建议重新上传，并在汇总里点名是哪几张；
- **聊天 / 文字截图按图里的结构记账**：不是票面时把图里文字逐行读回，只采信「人写的金额」那一类行，图里自己算出的合计不重复列；金额全部来自原文，记哪几笔由用户在待确认里决定，机器不替用户挑、不自动入账；
- **退款与重复按账实处理**：实付与退款两个数由识别读出、**净额由代码相减**（78 − 6 = 72，备注摆出三个数对账）；订单列表与付款凭证按**时间**配对（同一天且相差 ≤5 分钟算同一笔，金额只作附注），命中只说结论、没配到的如实列出并**点名是哪张图**；金额为 0 的订单行整个跳过（不建草稿，也不占汇总那句）；
- **拖拽导入与项目维度**：拖文件或拖整个文件夹，第一层文件夹名即项目名；**导入前会先问「这批账归哪个项目」**，没人建就替他建默认项目；当前项目＝列表最上面那个；账本按项目归集，发票号参与去重，项目改名不影响已入账的记录；删除项目有三种口径（只删项目 / 只删账保留项目 / 连同账单一起删），每一步都写清后果；**导入中途可以取消**（取消不报成「导入失败」，正在读的那张会跑完，已读出的草稿留在「待确认」里）；
- **报销表双源对账**：以表内数字为准，嵌入图的识别结果只用于核对，机器不覆盖人写的数；**核对可开关、默认关闭**（关掉时界面如实写「本次未核对表内嵌入发票」，不显示成「双源核对 0/0 张一致」）；
- **对话记账**：打一句话就记（Web 工作台是文字输入；语音走本机 ASR 脚本通道，需自行配置 `ASR_CLI` / `ASR_MODEL`），支持中文金额（三千 / 二九九 / 三百五）、多笔拆分、报销垫付语义；
- **多轮自由对话**：接入 LLM API 后支持连续追问与跨上下文（「那笔是哪天的？」「上个月花了多少」），未配置时自动回退规则兜底（本地零成本可用）；
- **识别 → 确认 → 入账**：记账与导入先生成待确认草稿，写入账本前必须由用户确认；左栏「待确认」面板加载即拉取草稿，逐笔可改**归属项目**与**分类**，可单笔或批量确认 / 丢弃（丢弃前先问一句，并写明账本不受影响；**丢弃是软删除，进回收站后可以一键撤回**，撤回不写任何账本事件），**不做一键直入账**；
- **接单决策最小版**：历史时薪由账本反推（收入中位数 ÷ 总工时），三道闸门（现金流垫底 / 回款周期 / 税后到手），报价下限 = 时薪 × 工时 ×（1 + 税负 + 抽成），每个数字可追到 `event_id`；缺「带工时的收入记录」时如实答「算不出」，不拿默认值假装算出报价；
- **真数据查询**：最近一笔收入/支出、本月支出分类汇总、现金流 30 天 90% 区间，数值全部由本地账本与状态引擎计算，LLM 不参与编造数值；
- **工时 / 开票 / 税务归集**：项目工时 Excel 自动认列并按人汇总出工资参考表；按客户生成开票清单；按季度归集收入，只归集事实，不算应纳税额；
- **事件账本 + 状态引擎最小版**：追加式 jsonl 账本、dedupe 幂等去重、SQLite 可重建投影、asOf 读取时计算（证据分级/健康度/状态标签）；
- **本机演示数据重置**：右上角「设置」里可把账本 / 待确认草稿 / 项目 / 工时表清空重来（录演示视频时反复重录用）；**重置不是删文件**——当前数据先整套备份到 `data/_reset_backup_<时间戳>/`，需要时整份拷回即可恢复，模型档位配置保留不动；另可一键「重置并载入演示样本」，让每次重录的开局一致（演示样本由 `python3 scripts/make_synthetic_business_ledger.py` 在本机生成，不入版本库）；
- **项目关账 + 三栏对账（2026-10-20 新增）**：项目详情里一条「关账对账」——**账面**（复用 `projects.summary`，与工作台同一个数）· **有账单凭证的收入**（只认微信 / 支付宝 / 银行通道）· **票据**（原文件 / 发票号 / 票据通道，三选一算有票），差额与缺票都给人话。**有几栏出几栏**：没导入过账单就不显示那一栏，绝不拿 0 冒充「到账 0 元」。关账只写一个 `closed_at` 时间戳，**账本一个字节不动**；
- **每一笔能追到那张票（2026-10-20 新增）**：确认入账时把草稿上的原文件名记进 `evidence_files.jsonl`（追加式对照表，不重写账本），最近记的账里显示「来源：xxx.jpg」；老事件没有记录就什么都不写，不补造；
- **空账本不塞示例（2026-10-20 定）**：新用户首屏就是「总账户 / 项目 / 你的账现在什么样 / 最近记的账」四块 + 一句开场白。试过示例卡与示例句胶囊，都撤了——一个用途不明的按钮点下去就有副作用（直接发了对话），比没有引导更糟；
- **账目导出 Excel**：一张明细（日期 / 项目 / 收支 / 分类 / 商户 / 金额 / 来源 / 备注 / 发票号 / 是否计入）＋ 一张汇总（项目小计、合计、支出分类小计、口径说明）；**金额写成数字、单位元**，客户可直接求和；同号重复发票在明细里标「重复·未计入」、在汇总里单列，不偷偷删。入口两个：左栏「总账目」右上角（全部项目）、项目行 ⋯ 菜单（单项）；
- **客户语言的界面**：预测区是「一个数字 + 一句范围 + 一行依据」，不再出现中位 / 下沿 / 区间这类词；数据不够时直说「再记 N 天就能推算」，不拿 0 或百分比冒充结论；左栏顶部是**总账户两张卡**（**绿 = 收入 / 红 = 支出**，2026-10-20 按主流记账心智改回来）；记账与导入产生的草稿都带日期；
- **记账字段由服务端确定，不交给模型猜**：项目名从「这笔记到 X」这类句式里确定性提取（优先级：文字里说的 > 模型给的 > 当前选中）；来源标签也由服务端定（模型常把打字的账猜成「语音」）；本机模型档位会**探测是否真的装了**，没装的标「本机未安装」而不是并列摆着当可用；
- **邀请码一码一账（线上已启用）**：`CASH_MULTI_TENANT=1`——每个码对应自己的数据目录与会话（码只存哈希、会话 HMAC 签名、换码即让旧会话失效），用于「一个地址给几个人用、各看各的账」。**本机默认仍是单用户模式，行为与以前一致**；登录页、部署件、PWA 壳均已上线；
- **创意阐述页**：三种用户场景、证据脚注（出处可溯源）、实弹验证记录、开发路线页（见 `docs/`）。

## 仓库概览

| 路径 | 职责 |
|:--|:--|
| `backend/` | FastAPI 后端：事件账本、状态引擎、四类输入通道（图片 / PDF / 报销表 / 账单）与页面类型判定、项目归集、待确认草稿、接单决策（报价下限）、工时与开票税务归集、查询工具、Excel 导出（明细 + 汇总）、邀请码会话（服务器上已启用，本地默认关闭）、对话 API（规则 + LLM 双通道） |

| `requirements.txt` | 后端运行时依赖（服务器 `python3 -m venv` + `pip install -r` 用） |

## 快速开始（原型阶段）

> **线上实例**：邀请制，一码一账，需要邀请码，未登录只显示邀请码页；**测试期只对内部试用开放，地址不在此公开**。本机开发按下述步骤启动即可。`docs/` 是产品介绍页（GitHub Pages），不含产品功能。

```bash
# 0) 配置环境（可选：不填 LLM API Key 时对话走规则兜底）
cp .env.example .env

# 1) 后端 API（事件账本 / 状态引擎 / 对话），在 backend 目录内：
python3 -m uvicorn app.main:app
# 端口需与 frontend/next.config.ts 里 /api 的代理目标一致（前端侧可用 CASH_API 覆盖）

# 2) 前端工作台（另开一个终端），在 frontend 目录内：
pnpm install && pnpm dev
# 打开终端提示的本地地址即可对话记账 / 查现金流

# 2b) 一键启动（不想敲命令时用）
#     macOS：双击仓库根目录的 启动-CashLens.command
#     它会自检依赖、首次自动安装前端依赖、同时拉起前端与后端，等就绪后打开工作台；
#     端口已有实例时先校验那是不是本仓库这一份（看账本路径与 /api/categories）：
#       · 是本仓库的**旧版本进程**（磁盘代码比它新）→ 停掉它，用最新代码在同一端口重启
#         （改了代码却一直没生效、新接口 404，多半就是撞上这条；判断依据是 /api/health 的 source_mtime）
#       · 是别的副本 → 让路到 8002 起，避免「新版前端配旧副本后端」
#     Windows：暂不提供一键脚本（旧脚本因端口硬编码、无副本校验已移除），按上面第 1、2 步启动。

# 3) 网页版创意阐述页：直接用浏览器打开 docs/index.html

# 4) 票据识别冒烟（识别 samples/ 合成样本）
python3 scripts/batch_recognize.py samples/

# 5) 测试
python3 -m pytest tests/            # 后端单测（当前 492 条）
node tests/demo_behavior.test.mjs   # demo 行为回归（当前 16 项）
```

> 语音识别依赖本机 ASR 工具与模型：通过环境变量 `ASR_CLI` / `ASR_MODEL` 指向本机可执行文件与模型（仓库不内置、不记录路径）。
> 启动后端 API 前请先在仓库根目录执行 `cp .env.example .env`；`.env` 已被 `.gitignore` 拦截，永不入库。

## 服务器部署（2026-10-19 上线）

线上实例：邀请制（一码一账），测试期只对内部试用开放，地址不公开

| 项 | 做法（**具体目录 / 面板 / 证书路径属运维细节，不放在公开仓库**） |
|:--|:--|
| 前端 | 本机 `python3 frontend/scripts/make_icons.py`（生成 PWA 图标，二进制不入库）→ `CASH_STATIC_EXPORT=1 pnpm exec next build --webpack` → `frontend/out/` → rsync 到 nginx 站点根目录；服务器上不装 Node、不跑 `next start` |
| 后端 | 发布目录放 `<release 目录>/<时间戳>/`，用一个 `current` 软链指过去；systemd 单元 `cashlens-api.service`，**单 worker（原型阶段的取舍）**，只监听本机回环地址（不对外开端口） |
| 环境变量 | 独立 env 文件（600 root）：`CASH_DATA_DIR=<数据目录>`、`CASH_MULTI_TENANT=1`、`CASH_COOKIE_SECURE=1`（`CASH_LOCK_MODEL` 已于 2026-10-20 移除，见下） |
| 数据 | `<数据目录>/`（700，仅服务账号可读），一码一个 `tenants/<slug>/`；`tenants.json` 与 `session.key` 在根目录 |
| nginx | 站点配置托管在本机反向代理配置里；`/api/` 反代到后端服务，`proxy_buffering off`、900s 超时、`client_max_body_size 128m` |
| 证书 | Let's Encrypt，acme.sh 每日检查、自动续期（备用证书留同目录） |
| 备份 | 每日定时把 `<数据目录>` 备份到备份盘，保留 14 天；已实测可还原 `tenants.json` / `session.key` |
| 健康检查 | 定时探 `/api/health`，探不到就重启服务 |
| 邀请码 | `python3 scripts/manage_tenants.py create --label "客户A"`（码只显示一次，库里只存哈希；`list` / `rotate` / `revoke` 同脚本）。⚠️ **建完要 `chown -R <服务账号> <数据目录>/tenants/<slug>`**，否则该租户所有接口会因权限 500 |

> 改前端的流程＝本机重新导出 + rsync `out/`；改后端＝新建 release + 切 `current` + 重启服务。
> **模型档位按账号各存一份**（2026-10-20）：落在 `<数据目录>/tenants/<slug>/model_config.json`，界面上可各自切换云端 / 自定义端点，互不影响。服务器自带的 `LLM_API_KEY` 不落进租户文件（写盘存哨兵 `__from_server_env__`，读时换回环境变量真值，换 key 时所有租户自动跟上）。运维仍可用 `CASH_LOCK_MODEL=1` 临时全站只读。⚠️ 线上这台机器的配置不够，跑不了本地视觉模型——界面里的「本地」指**用户自己机器 / 内网的端点**。

## 安全与隐私

- `.env`（密钥）、`data/`（本地账本/状态库/待确认草稿）、用户上传数据目录一律不入库（见 `.gitignore`）
- 账本与金额计算始终在本地磁盘完成；金额与现金流数值不依赖任何外部服务
- 启用云端 LLM 时，对话文本与**需要识别的票据图像**会发送给所选服务商；数据流向与各档位边界集中写在产品「关于」页与本仓库的合规说明里。选「本地模型」或「不用模型」时不外发；带文本层的数电票 PDF 走本机解析
- 网页演示在浏览器本地完成，不采集任何数据
- 纪律：AI 自报不可信 —— 本仓库每个对外声称都尽量带真实实测证据或如实标注"示意/规划"

### 提交前隐私闸（防「真实客户数据」再次入库）

`.gitignore` 只挡得住"已知目录与文件类型"，挡不住**客户名被写进代码、测试夹具或提交信息**。所以另有一道闸：

```bash
bash scripts/install_privacy_hook.sh     # 装到 .git/hooks/pre-commit（换机器/重新 clone 后需重装）
python3 scripts/check_privacy.py --all   # 事后审计：扫全部已跟踪文件
```

它做两类检查：

1. **黑名单**（已知客户的公司名 / 项目名 / 商户名 / 联系人姓名）—— 清单**故意放在仓库之外** `../.privacy/real-names.txt`，因为清单本身就是隐私；清单缺失时闸门 fail-closed（拒绝提交），不许静默放行。
2. **通用模式**（还没进清单的客户）—— 20 位发票号、微信导出文件名、手机号、身份证号、中文公司名。

命中时打印 `文件:行号`；确属正当用途的，在该行行尾写 `privacy-ok` 显式放行（留痕，不静默）。合成发票号请用 `2631…`（26=年份、31=区划，能过票号校验）。`git commit --no-verify` 可以绕过——绕过即视为放弃这条纪律。

> 起因：客户公司名与项目名曾经进过 14 个已跟踪文件并推到公开仓库，靠重写 100 个提交才清干净。**事后补救永远有残留窗口，纪律必须前移到提交之前。**
